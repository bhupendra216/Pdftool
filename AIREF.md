## 1. Project Overview and Purpose

This is **PDFKira**, a free, premium-feeling PDF utility web application. It provides a collection of browser-based PDF tools (merge, split, compress, convert, organize, OCR, etc.) with a polished UI inspired by iLovePDF. The project is currently in an **MVP/site-shell phase**: the frontend tool catalog, marketing pages, blog, and admin shell exist, while real file-processing capabilities are being added incrementally.

The repository is a **pnpm workspace monorepo** containing:
- A React + Vite marketing/tool frontend
- An Express API server for PDF processing and CMS operations
- A mockup/design sandbox for isolated component previews
- Shared libraries for API contracts, validation schemas, and database schema

## 5. Important Patterns, Conventions, and Architecture Decisions

### API-First Contract
- The OpenAPI spec in `lib/api-spec/openapi.yaml` is the source of truth.
- **Do not change the `info.title`** ("Api") — changing it breaks generated import paths.
- Run `pnpm --filter @workspace/api-spec run codegen` to regenerate:
  - React Query client → `lib/api-client-react/src/generated/`
  - Zod schemas → `lib/api-zod/src/generated/`

### Zod Version Constraint
- The workspace pins **Zod v3** in the pnpm catalog.
- **Do not use `format: email`** on string schemas in `openapi.yaml` — Orval emits `zod.email()`, which only exists in Zod v4. Use `type: string` with `minLength: 1` and validate email shape at the application layer.

### TypeScript Project References
- Root `tsconfig.json` uses project references.
- Run `pnpm run typecheck:libs` (or `pnpm run typecheck`) to typecheck the whole workspace in dependency order.

### Package Import Conventions
- Frontend uses `@/*` path aliases mapped to `src/*`.
- Cross-workspace imports use `@workspace/*` package names.

### Database Status
- PostgreSQL and Drizzle are provisioned/configured but **currently unused** at runtime.
- Tool catalog, blog, FAQ, and AI jobs content are static data files or server-side in-memory data.
- No user accounts or persistent sessions yet.

### Admin Authentication
- Admin routes exist (`src/routes/admin.ts`, `src/lib/admin-auth.ts`, `src/lib/admin-store.ts`).
- Implementation details should be verified before assuming production-grade security.

### Logging
- API server uses **pino** for structured JSON logging with pretty printing in development.

### PDF Processing Stack
- Document manipulation: `pdf-lib`
- PDF rendering/extraction: `pdfjs-dist`
- OCR: `tesseract.js`
- Image conversion/manipulation: `sharp`, `jimp`, `heic-convert`, `potrace`
- Office documents: `docx`

### Frontend Build Note
- `artifacts/pdf-tools` commits static output; its `build` and `vercel-build` scripts currently echo "skip build".

### Security Policy
- `pnpm-workspace.yaml` enforces a **1-day minimum release age** for npm packages as a supply-chain defense.
- **Do not disable this setting**. If a package is needed urgently, add it to `minimumReleaseAgeExclude` and document why.
